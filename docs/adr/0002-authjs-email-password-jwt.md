# Auth.js with email and password and JWT sessions

Animelix uses Auth.js (NextAuth) with the Credentials provider for email and password, and the JWT session strategy. The trade-off was against passwordless magic links, OAuth-only providers, and hosted auth like Clerk. Magic links would have removed the need to store and hash passwords but require reliable transactional email delivery on every login, which is one more external dependency; OAuth-only excludes users without GitHub or other configured providers, and Clerk adds vendor lock-in. Email and password with JWT sessions keeps the dependency surface minimal and the auth flow predictable; the cost is the responsibility for password hashing, reset flows, and rate-limiting login attempts. JWT sessions (instead of database sessions) keep auth stateless and remove a database round-trip on every request, at the cost of not being able to revoke a session server-side without rotating the secret.
